Hack Nov 2024: Materialized views in Atlas Stream Processing
What’s the goal
Get this working
The topAccounts collection incrementally maintains the accounts with a large balance.
sp.createView("topAccounts",
[{$match: {balance: {$gt: 500}}}],
"cluster1.db.accounts",
"cluster1.db.topAccounts")
And get this working
sp.createView("totalOrders",
[{$group: {_id: "$customerId", total: {$sum: "$cost"}}}],
"cluster1.db.orders",
"cluster1.db.totalorders")
The totalorders collection is an “incrementally maintained” view of the orders collection.

How
Initial snapshot
In the changestream background thread, run find() on the collection. Start changestream from logical timestamp <= the timestamp of the initial query.
Handle updates and deletes
Delete support in sink
Transform changestream into StreamDocument with bool isDelete set
Update generates an Insert followed by Delete
Planner logic
Prepend ChangeStreamSourceOperator and append SinkOperator
GroupOperator
Support incremental group outside of window
Should we productize this?
Yes and no
Supporting $group in the top level pipeline is a good stepping stone towards full MV support... Full support for materialized views is a lot of work.
Support for $group in the top level pipeline (group on an entire stream)
Medium-sized project (ignoring problems of scale)
Fits nicely into existing syntax structure, i.e.
sp.createStreamProcessor(“avgOrderCost”, [
{ $source: { connectionName: “cluster1”, db: “test”, coll: “orders” } },
{ $group: {
_id: “$customerId”,
avgOrderCost: {$avg: “$cost”}
} },
{ $merge: { into: { connectionName: “cluster1”, db: “test”, coll: “orders” } } }
])
Full on materialize views. I.e., take an agg query, plop it into an ASP materialized view
Large project, a new-ish product paradigm
Good opportunity to feel more similar to the database product
Need the following
Initial sync support
Delete and update support
Incrementally maintained aggregation and sorting
Transactional support
Exactly once or “always idempotent” processing guarantees
It could look like this, while connected to your DB cluster:
db.accounts.createView(
“topAccounts",
[{$match: {balance: {$gt: 500}}}],
materialize: {
spi: “mySPI”,
outputNs: “"cluster1.db.topAccounts”
}
)
